This alpha completes the rename from meshFlask to **stl-sherpa** and adds installer acceptance checks before release drafts are created.

## Changes

- Updated application branding, installer names, renderer bridges, and documentation.
- Existing meshFlask profiles, library IDs, tags, notes, ratings, custom thumbnails, preferences, and saved UI state are retained. Catalogs and cache folders intentionally keep their legacy `.meshFlask` names; no manual migration is needed.
- Added a Debian package with an application-specific AppArmor profile for Ubuntu 24.04.
- Added installed-package acceptance tests for Windows, Apple Silicon, Intel macOS, and Linux. Linux release checks retain Ubuntu's user-namespace restriction and Chromium's sandbox.
- Fixed packaged-test startup timeouts and cleanup of AppImage child processes on hosted runners.

## Downloads

- **macOS:** choose the ARM64 DMG for Apple Silicon or the x64 DMG for Intel. Builds are signed and notarized; ZIP alternatives are included.
- **Windows:** run the x64 setup executable. This alpha is unsigned, so Windows may display a SmartScreen warning.
- **Ubuntu 24.04:** prefer the AMD64 `.deb`, installed with `sudo apt install ./stl-sherpa_*_amd64.deb`.
- **Linux AppImage:** Ubuntu 24.04 requires the included `stl-sherpa-appimage.apparmor` profile and the documented `/opt/stl-sherpa.AppImage` installation path. See the [installation instructions](https://github.com/mthorson/stl-sherpa#installing-on-ubuntu-2404).

`SHA256SUMS.txt` covers every installer and the AppArmor profile.

## Validation and remaining limits

The release workflow gates this draft on native installer launches, packaged SQLite and thumbnail workers, all six supported model formats, glTF external resources, and persistence after restart. macOS packages additionally pass signature, Gatekeeper assessment, and stapled-ticket checks. The rename upgrade is tested locally against the original meshFlask alpha.1 AppImage.

Automated checks use generated models and software rendering. They do not replace hardware-GPU testing, browser-download quarantine prompts, physical SMB/NFS disconnect testing, or acceptance with large real-world slicer exports. Large multipart Bambu 3MFs still use an embedded preview fallback; background thumbnails still render at Low quality.
